# MS-OFORMS Persistence Fact Tooling

This directory owns the deterministic W010 persistence/default capture for
`oxforms-jbjp.3`. It reads only the pinned, public MS-OFORMS revision in the
sibling Foundation repository and emits the committed row-level fact pack.
It is durable evidence infrastructure and is never imported by production VBA
or Rust.

## Commands

From the OxForms repository root:

```powershell
python -B tools/ms-oforms/export_ms_oforms_facts.py
python -B tools/ms-oforms/export_ms_oforms_facts.py --check
python -B tools/ms-oforms/validate_ms_oforms_facts.py
python -B tools/ms-oforms/validate_ms_oforms_facts.py --require-sources
python -B -m unittest discover -s tools/ms-oforms/tests -p 'test_*.py'
```

The ordinary validator is standard-library-only and does not need Foundation.
`--require-sources` verifies the exact Foundation commit, hashes every pin from
that commit blob and from its separately clean working-tree path, then rebuilds
the facts. Export `--check` performs two independent source reads, requires
identical generated bytes, and compares them with the committed artifact.

## Inputs and boundaries

`pinned_sources.v1.json` pins MS-OFORMS 9.1 (2025-08-19), the authoritative
DOCX/PDF, Foundation run index and manifests, normalized DOCX segments, and all
six figures referenced by the selected rows. Text artifacts are hashed after a
strict UTF-8 `CRLF -> LF` normalization; bare CR is rejected. This avoids a
checkout-dependent pin while raw documents and images remain byte-for-byte
pinned.

The selected contiguous segment span is partitioned into separately classified
ranges: persistence context, normative structures/defaults/algorithms, worked
examples, security context, and Appendix A product behavior. The normalized
capture's original tool worktree was dirty; that caveat is pinned and preserved
even though the published Foundation commit is clean.

The generated pack preserves every selected heading, paragraph, table cell,
blank marker, coordinate, and figure reference. Its derived surfaces normalize
records and aggregate requirements, bitfields and qualifiers, properties and
value domains, typed defaults/ranges, enumerations/value maps, algorithms,
resource codecs/formats, product notes, and unknown handling. Every modal clause
has a concrete operation class. Runtime API claims and oracle rows are
deliberately empty. Referenced external standards are inventoried but not
silently represented as captured facts.
